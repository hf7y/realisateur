# Retired mandark loop scripts — 2026-08-05

The 12 files beside this README were mandark's `~/.local/bin/*-loop.sh`
dispatch wrappers. They are copies, taken with `cp -p` before deletion; the
originals are gone from `~/.local/bin` as of 2026-08-05.

## Why they went

They were the pre-`scheduler-run` generation: hand-written wrappers that set a
few variables and sourced `lib/sweep-loop-common.sh`. `scheduler/MIGRATION.md`
describes the move that made them redundant — a tier's config lives in
`schedule/<project>.conf`, and the generic `bin/scheduler-run` reads it.

By 2026-08-05 nothing invoked any of them on mandark:

- **mandark's crontab does not reference them.** It was deliberately emptied on
  2026-07-29 (realisateur, Zach-directed) for THE PLAY run 3, and only two
  lines have since been regenerated — the arme monitor tick and the scheduler
  sweep backstop. Backup of the pre-emptying crontab:
  `../crontab-backups/mandark-crontab-2026-07-29T1425.bak`.
- **`schedule/_paced.conf`'s rows pointed at five of them, all `enabled=0`.**
  Those rows are retired in the same change; see that file's header.
- **`services/*/schedule.txt` names four more in its `script:` lines.** That
  view is generated by `scheduler/bin/build-services-view.sh` and already
  reports `in crontab: no` for them.

THE PLAY run 3 is declared concluded (Zach, 2026-08-05). Its premise was that
scheduler should bring dispatch back up itself rather than inherit a crontab
nobody generated; self-dev has since moved to monkey's four per-project
accounts, so mandark is not where that dispatch is coming back.

## Why they were kept rather than deleted outright

`scheduler-nightly-batch-loop.sh` is 7.6K and is the only remaining record of
how that tier was configured before the migration; `wtul-batch-loop.sh` has a
`.pre-scheduler-migration.2026-07-27` sibling that is itself an earlier
rescue. If a conf field turns out to have been lost in the move, the wrapper
it came from is here.

Nothing here is on `PATH` and nothing reads this directory. Restoring one is a
deliberate `cp` back into `~/.local/bin`, not an accident.
