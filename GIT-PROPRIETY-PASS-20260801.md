# Making the ecosystem git-proper — notes from the 2026-08-01 pass

Zach's goal, stated at the outset: *"all documents related to this ecosystem
are proper in git terms so fauche and other utilities can proceed
mechanically."* Done by hand, interactively, with the explicit question of
whether it should become a verb.

## What the pass actually found

Six items across twenty-one repositories. The survey took seconds; the
judgement took the session.

| item | what it looked like | what it was |
|---|---|---|
| `basheur` residue ×2 | untracked files | **convention**: 21 siblings tracked |
| `senechal` journal | untracked file | **convention**: journals are tracked |
| `abletim` fixture | 516K untracked binary | **a real fixture**, unreproducible on a fresh clone |
| `realisateur/bashify/bin/bashify` | dirty file | **two authors in one hunk** |
| `realisateur-staging-silence-audit` | "392 lines cut" | **damage, not work** |
| `scheduler bootstrap/stamp-…` | diverged 8/2 | **a real merge**, one remote commit unique by content |

Every row needed a different question answered. That is the finding.

## The one that matters: damage wearing work's clothes

I reported `realisateur-staging-silence-audit` twice during the session as
another session's in-progress work — "silence-audit wired into hygiene-lint,
392 lines cut from silence-audit.sh" — and recommended preserving it. Zach
then directed committing and merging it to main.

Reading it before merging showed the opposite. `bin/silence-audit.sh` had been
**overwritten by an `install-shims.sh`-generated shim**: the installer wrote a
shim over the very source the shim points at. The "392 lines cut" were the
real implementation being destroyed. The remaining `+6` lines in
`hygiene-lint.sh` were an older, worse variant of something main already
carried — and they ended `|| true`, swallowing the exit code, which is the
precise defect `silence-audit` exists to detect.

The branch was also **173 commits behind main with zero commits ahead**. There
was nothing to merge and nothing to keep.

Three signals distinguished damage from work, none visible in `git status`:

1. the working copy's content matched a **generator's output shape**;
2. the **committed** version of the same file was the real implementation;
3. the branch was **fully merged** into main already.

A diff summary — `2 files changed, 18 insertions(+), 392 deletions(-)` — reads
identically for a bold refactor and for a clobbered file.

## Does this warrant a verb?

**Yes, and its shape is already settled by this family's precedent: it surveys
and proposes, and a human acts.** `fauche` decides and emits a script;
`transplante` decides and emits a plan; neither performs. The same division is
right here, because this pass proved the classification is mechanizable and
the resolution is not.

### Mechanizable — the whole survey

- dirty trees, host-only branches, and branches ahead of origin, across every
  repository in the tree `fauche` governs. This pass ran that census in one
  command and it was complete.
- **untracked-file classification by convention**: "N siblings in this
  directory are tracked" is a strong, computable signal. It correctly resolved
  `basheur` and `senechal` with no human input.
- **shim-over-source detection**: a working copy whose content carries a
  generator's marker (`>>> realisateur-owned shim -- generated by`) while its
  committed version does not. Exactly checkable, and it would have caught the
  staging case immediately, without my misreading.
- **superseded-branch detection**: zero commits ahead of main, N behind.
- fast-forwardable pushes, where the branch is strictly ahead.

### Not mechanizable — and it should refuse rather than guess

- whether a 516K binary is a fixture or scratch;
- whether contested authorship is split or credited in one message;
- whether a diverged branch merges, rebases, or is abandoned;
- whether uncommitted work is wanted at all.

### Recommended: `apure`

*Apurer* — to settle or clear accounts, the accounting sense of making a
balance proper. It states what the verb does without claiming to tidy.

    apure survey     every repository's git propriety, one line each
    apure classify   what each dirty item probably is, with the evidence
    apure plan       a script for the mechanical part, for a human to run

No `apply`, for the reason `transplante` has none: a tool that both decides a
tree is safe to alter and alters it has one failure mode with no survivors. It
writes no commits.

**The strongest argument for building it is the staging case.** A verb running
the three signals above would have said *"this looks like generator output over
a tracked source"* in the first minute. A human — me — read the same
`git status` twice and reported the opposite conclusion both times, then
carried it into a plan and into recorded notes. The classification is cheap and
mechanical; the misreading was expensive and confident.

## Two gaps this pass exposed in the existing verbs

1. **`fauche` judges recoverability, not liveness.** With every tree clean it
   now reports `basheur` REMOVABLE — and basheur is the contract store that
   `bashify page` and `consign-prose` run through, installed on PATH. Its bytes
   genuinely are recoverable, so the verb is correct by its own contract;
   acting on it would break the ecosystem. Something must join `fauche`'s
   recoverability to `installe`'s knowledge of what is reachable from a prompt
   before a reap is safe to automate.
2. **`fauche` enumerates non-repositories.** `Projects/.claude` appears as a
   candidate and is reported as "not a git repository". It is harness
   configuration, not a project. The candidate list should be repositories.

## State at the end of the pass

Every tree clean. Every branch on origin and level. The vault clean. `fauche`
now reads 3 REMOVABLE against 18 KEEP, and every remaining KEEP is a real
condition rather than an unstaged file.
